# Wildbound P0: Fog Forest greybox

## Intended loop

An editable 400 × 400 stud square, centered at the origin, with ground top at Y = 0.5. The 14-stud-wide route connects camp (-140, 140) → Lumipol clearing (-95, 75) → ruin (0, -85) → egg nest (35, -99) → marsh (115, 15) → shelter (105, 125) → camp (X, Z coordinates). This is a prototype route, not a measured traversal time or final world boundary.

The nest sits 37.7 studs from the guardian home, inside the 80-stud leash, so the main objective carries encounter risk.

Markers are invisible, anchored, non-colliding placeholders; they are not spawn points or gameplay implementations. The amber camp, cyan clearing beacon, stone ruin/nest, teal pool, and shelter are primitive stand-ins. The builder still places fixed-seed greybox trees (`TreeTrunk`, `TreeCrown`); the forest dressing below replaces them. Decorations do not collide. Route sightlines and landmark readability require playtesting, not inference from this design.

## Forest dressing

`tools/dress-wildbound-forest.luau` exports `dress(root, templates, instances)`. It removes only the `TreeTrunk` and `TreeCrown` placeholders from `root.Decorations`, then adds `Decorations.ForestKit`: one Model per layout instance (207: 130 evergreens, 42 dead trees, 17 logs, 1 root arch, 1 ruined doorway, 16 lanterns), named by its layout `id`. Each is a clone of a `ServerStorage.WildboundAssets.ForestKit` template with its `PackageLink` removed, scaled with `ScaleTo`, and pivoted to `(x, 0.5, z)` with yaw `rotation_y_deg`. The root is untouched until every prop is placed, so an unknown prop, a missing template, bad layout data, an existing `ForestKit`, or a failure midway leaves it as it was. Placement yields every 12 props.

- Source of truth: `assets/maps/forest-layout/forest-layout-v1.json`. Studio reads it as `ServerStorage.WildboundForestLayout` (the `instances` array, which also carries `totals`, `inputs` and `nest_cover` for tests), generated by `tools/export_forest_layout_luau.py`; compare its `--adler32` with the Studio script source after pasting.
- Every part is anchored with `CanCollide` and `CanTouch` off.
- Line-of-sight rule: the guardian's sight check (`WildboundWorld.server.luau`, `visible`) raycasts against everything with `CanQuery` on. Only `FK_Evergreen_Trunk` and `FK_DeadTree_Wood` have it on, so what the player sees as a trunk blocks sight; canopies, splinters, logs, arches, doorways and lanterns never do. `RuinPillar` keeps blocking as before. The plan relies on the pillars for patrol S and W and on open lines from E and N to the nest.
- Trunk fidelity: those two template parts use `PreciseConvexDecomposition`, so a ray follows the real trunk (3 to 4 studs wide at eye height). `Box` blocks about 12 studs across the root flare and `Hull` about 10. Studio applies a new fidelity only after a yield, and a detached clone ignores it, so it is set on the templates and clones inherit it. A reinserted or package-updated template loses it; the dress test fails if that happens.
- Pivots stay 7 studs or more from every route centerline, except the arch and doorway, which straddle the route with their gap centred on it.
- Moving a root that holds dressed models: use `PivotTo`; `TranslateBy` leaves nested model pivots behind.

`tests/WildboundForestDress_Test.luau` runs on fresh clones of the builder, the dress module, the layout module and the templates. It builds into a detached Folder; only its raycast checks park the dressed root in a uniquely named Workspace folder 5000 studs from the map and remove it.

## Construction and safety

`tools/build-wildbound-p0-map.luau` exports `build(parent)`. It refuses an existing `WildboundP0`, builds a detached editable Model, then attaches it to the supplied parent. It never removes unrelated content or alters Terrain, Lighting, spawn settings, or assets. The ground and paths are collidable; cosmetic geometry is not. The geometry is a greybox without boundary walls; players can leave it unless the surrounding environment prevents that. It does not set global fog.
